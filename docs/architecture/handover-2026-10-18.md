# NetVoyager session handover — 2026-10-18

## Completed changes

- Introduced the `netvoyager-intelligence` distribution for evidence and findings
  models and in-memory stores. Analysis declares the new dependency.
- Preserved evidence/finding identities, timestamps, exceptions, insertion
  ordering, link semantics, and native Python detail values. Temporary Analysis
  re-exports retain class identity for existing consumers.
- Added two migration tests for compatibility imports and store operation.
- Included the SQLAlchemy Database foundation: engine/session configuration,
  SQLite foreign keys, canonical-device repository, candidate/relationship
  entities and mappers, and explicit Unit of Work transaction handling.
- Moved discovery models/store to Network, retaining Analysis compatibility
  modules and the Analysis evidence aggregation helper. Corrected invalid
  cross-package imports left by relocation.
- Moved repository and Unit of Work Protocols into Analysis without changing
  their interfaces. They remain structural contracts, without implementation
  inheritance requirements.
- Consolidated persistence exceptions in Database using Core's error hierarchy.
  Updated consumers and removed the Storage distribution and dependency.
  Existing exception names and error codes remain unchanged.

## Validation

Using the workspace `.venv` interpreter with each local package's `src` on
`sys.path`, the combined Intelligence, Analysis, and Database suites ran with
`--import-mode=importlib`: **171 passed, 9 failed**. Database's 46 tests pass.

The nine failures are in unchanged IPAM tests and implementation files:

- Seven ASN tests construct `AsPrefix` without its required `source_id`.
- One prefix-store test supplies an unsupported explicit `NetworkPrefix.id`.
- One expects a duplicate-network error where deterministic identity produces
  a duplicate-ID error first.

These IPAM model, store, and test paths were compared with HEAD and have no
changes in this session. They require a separate test-contract review.

Protocol imports, repository return annotations, Core exception hierarchy and
structured error payloads, and documentation links were also checked. No live
Panorama workflow or persistent-database upgrade was run.

## Next steps and open decisions

1. Review the unrelated IPAM test contracts against source-aware BGP identity
   and deterministic prefix IDs; do not change identity to satisfy stale tests.
2. Choose Intelligence persistence representation after examining real callers:
   dataclasses plus Database entities/mappers versus ORM-native records.
3. Keep concrete Database imports in Analysis a separate explicit decision.
4. Design evidence persistence: native detail serialization, UUID versus string
   object IDs, timestamp normalization, retrieval ordering, and shared transactions.
5. Decide evidence referential integrity before replacing discovery relationship
   JSON UUID lists. They currently provide references without evidence FKs.
6. Implement discovery SQL repositories, decision persistence, and UoW integration
   incrementally. Current inventory UoW exposes the canonical-device repository.
7. Review assertions, findings lifecycle, and audit ownership separately; the
   Intelligence extraction does not authorize moving all those models.

Network models remain independent of SQLAlchemy. Evidence remains provenance,
not a device-identity matcher. Applications configure Core logging; exceptions
do not log themselves. Compatibility modules remain until consumers migrate
and regression tests permit removal.

## Migration and rollback considerations

External Storage consumers must change Protocol imports to Analysis and exception
imports to Database. Environments with old editable Storage installs may require
dependency resynchronization. Compatibility imports for evidence/findings remain.

The relocation and Storage removal require no data migration. The new Database
foundation is tested with fresh SQLite in-memory schemas; persistent deployments
need reviewed Alembic migrations before adopting new tables. Roll back package
moves together with consumer imports and dependency metadata.
